# PC input initialization and binding load

Status: confirmed action-mask/action-state path and first action-dependent movement producer; downstream movement semantics remain partial
Build: `f2c7ca7cbc31abd8f748bd4afdc1e30aa1a6700ce91893b618450fd16172669c`
Addresses: `0x004e4690`, `0x004e4d10`, `0x004e4a90`, `0x004e42c0`, `0x004699f0`, `0x00469de0`, `0x00489930`, `0x00489a10`

## Observation

- `0x004e4690` contains the diagnostic `InitDirectInput`, creates/acquires DirectInput keyboard, mouse, and joystick devices, and calls `0x004e4d10` during initialization.
- `0x004e4d10` contains the exact diagnostic `PCINPUT_Load`.
- Its decompilation reads ten configured control values, including the entries corresponding to grind, jump, spin, nollie, switch, pause, and camera. It resolves `JOYPAD` and `KEYBOARD` bindings, validates duplicates and key ranges, then calls the input-device setup helpers.
- The current `TH2_OPT.CFG` runtime configuration matches this path: movement uses arrow/WASD bindings and trick actions use the configured keyboard keys.
- The configured trick bindings are distinct: `JUMP=PAD2,SPACE,RETURN` while `KICK=PAD6,B`. The action-mask builder preserves that distinction as bit `0x0010` for JUMP and bit `0x0040` for KICK; the physics prephysics gate later consumes the KICK record at player action-bank offset `+0x30`.
- `0x004e4a90` is the per-loop DirectInput poll called from `0x00489a10`. It updates the keyboard device, polls the optional joystick, refreshes mouse state, and handles Alt-F4.
- `0x004e42c0` converts the polled bindings into the per-player action mask at `DAT_006a3f1c`; `0x004e4650` exposes that mask to the higher-level action update.
- `0x004699f0` calls the input-history/update chain (`0x00489cd0`, `0x00489a10`, `0x00489e70`) once per level-loop iteration. `0x00469de0` follows it and is a stable post-poll sampling point.
- The repeatable GDB collector `tony-input-sample COUNT FILE [--force]` records the action mask, held DirectInput scan codes, and the 256-byte keyboard state after the poll. The keyboard wrapper is at `0x006a43e0`; its state buffer is at `0x006a43e4` (`+4`).
- A controlled Warehouse run held Left while sampling 80 post-poll iterations. The companion player trace showed stable player/owner pointers and movement in the position-like 16.16 fields at offsets `0x08/0x0c/0x10`, `0x90/0x94/0x98`, and `0xbc/0xc0/0xc4`.
- The dynamic input trace now distinguishes idle from held input: 30 idle Warehouse samples had action mask `0x0000`, while held-key samples at level `12` produced Left `0x8000` (60/60), Right `0x2000` (20/20), Up `0x1000` (20/20), and Down `0x4000` (20/20). This confirms the complete keyboard movement-to-action-bit mapping.
- The corrected sampler captured DIK_LEFT (`0xcb`) as held byte `0x80` in the DirectInput buffer while the action mask was `0x8000`; idle capture produced no held scan codes.
- Native `InputBindings` now preserves this boundary as a data-driven 256-byte keyboard-state mapper. Its movement defaults use the confirmed DirectInput arrow scan codes `0xcb/0xcd/0xc8/0xd0` for action bits `0x8000/0x2000/0x1000/0x4000`; all other configured action bits remain caller bindings.
- The movement action-state records are 16 bytes each at `0x0056b078` (Left), `0x0056b088` (Right), `0x0056b098` (Up), and `0x0056b0a8` (Down). A held-Left trace at the state-update chain observed `byte0` changing `0 -> 1` at `0x00489966` and returning `1 -> 0` at `0x0048996a`; `byte1` changed `0 -> 1` once at `0x00489951`, identifying it as a press-edge latch candidate.
- `0x00489a10` maps the polled action mask into these 16-byte records through `0x00489930`; `0x00489930` only advances active/inactive state and counters. Its decompilation contains no player-object writes, so the movement consumer lies later in the gameplay/skater update path.
- The later consumer is now identified statically and dynamically as
  `0x00493370`: it reads the directional records through the player action
  bank pointer, updates movement-target candidates at `player+0x3144` and
  `player+0x3148`, and runs before the main physics dispatcher. The complete
  12-record bank is retained by the physics probe so trick, jump, and movement
  edges can be correlated on the same frame.
- The later action-table path is distinct from direct movement: `0x00492120` reduces profile flags at `+0x2ccc+0x80/+0x90/+0xa0/+0xb0` and skater analog/lean bytes `+0x31a2/+0x31a1` to a table entry, `0x00492190` publishes that entry as action records `1..8` and profile flags as records `9..0x10`, and `0x004925e0` consumes the configured action table into animation/trick events. This chain does not write the live position or response vector and is separate from the `0x00493370` movement producer.
- The action/trick asset load is now bounded. During level-side setup, `0x0046a250` calls `0x00492a90` after the skater resources are prepared. `0x00492a90` loads `tricks.bin` and treats its leading signed-16-bit words as internal section offsets: section 0 (`0x00ac`) is a 20-entry selector for player-input short-record tables, whose trailing stream offsets resolve against the loaded image; section 1 (`0x3440`) is adjacent action metadata, and sections 3/4 (`0x7990`/`0x7d90`) are the per-player table destinations. `0x00492de0` performs the same load/build path on demand and `0x00492b20` tears it down.
- The post-load build path is also concrete. `0x00492de0` calls `0x004bd1e0`, which builds the per-player action table, then `0x00492d50` walks each generated sequence: it resolves a signed-16-bit stream offset directly against `DAT_0056a894`, and `0x00492d10` walks that stream with the command-width helper `0x004bf6c0`. At runtime `0x004925e0` scans the active sequence table, matches the current action-record history, and passes the selected stream pointer through `0x00492290` to the action-stream state at `+0x29cc`. The generated record layout is now conservative but concrete: a signed length, that many action IDs, a signed stream-relative offset, flags, then the next record; zero length terminates. Source section `0x1736` contains 596 such records and section `0x161a` contains 27; the retail constructor registers their stream/flag metadata in `0x28`-byte heap records before `0x004bcf00` filters them. Native `assets::TricksBinView` exposes bounded source tables and direct image-relative stream resolution; `runtime/action_sequence.*` owns the 32-entry action-history ring and bounded matcher; and `PlayerState::run_action_sequences()` can resolve a generated or explicitly selected source record to a real archive stream before invoking the command dispatcher. Native `runtime/action_sequence_builder.*` now ports the deterministic ordinary/static/mapped passes of `0x004bcf00`; its unresolved runtime resource IDs remain explicit inputs. The shipped `0x7990`/`0x7d90` regions remain zero-filled placeholders and are not mistaken for final records. Native physics can still opt into the shipped source table as an explicit fallback for fixtures that do not supply the builder inputs.
- The full `0x00489a10` profile-block mapping is now recorded. At the action-state base (`DAT_0056aff8`, stride `0x16c`), `+0x00/+0x10/+0x20/+0x30/+0x40/+0x50/+0x60/+0x70` consume raw mask bits `0x10/0x80/0x20/0x40/0x4/0x1/0x8/0x2`; `+0x80/+0x90` are Left/Right from `0x8000/0x2000` or horizontal axis thresholds `<=-0x29/>=0x29`; `+0xa0/+0xb0` are Up/Down from `0x1000/0x4000` or vertical axis thresholds `<=-0x29/>=0x29`; and `+0xc0/+0xd0/+0xe0/+0xf0` consume `0x200/0x400/0x800/0x100`. This is a slot mapping, not a final gameplay naming assignment.
- The binding-load call order resolves the first eight non-directional names: `+0x00` is JUMP (`0x10`), `+0x10` is GRAB (`0x80`), `+0x20` is GRIND (`0x20`), `+0x30` is KICK (`0x40`), `+0x40` is NOLLIE (`0x4`), `+0x50` is SPINRIGHT (`0x1`), `+0x60` is SWITCH (`0x8`), and `+0x70` is PAUSE (`0x2`). Thus B010's stronger `+0x10` profile gate is specifically the configured GRAB action; the remaining `+0xc0..+0xf0` names are still kept by offset pending their exact consumer mapping.
- Native `ActionProfileState` mirrors those sixteen slots and retains the normalized axes. `PlayerPhysicsFrameResult::action_profile` captures the materialized block for every frame, and the `FUN_0049b010` ground-motion hook receives it before the correction producer runs. The native test covers every raw slot plus the exact analog boundary behavior.
- `0x00492120` computes its action-table index as `byte(+0xa0) + 2*(byte(+0xb0) + 2*(byte(+0x80) + 2*byte(+0x90)))`, then ORs bits `1/2/4/8` for skater `+0x31a2/+0x31a1` below/above `-0x28/+0x28`. `0x00492190` republishes selected table entries as records 1--8 and raw profile slots `+0x20/+0x10/+0x30/+0x00/+0x50/+0x70` as records 9,10,11,12,14,16. The table path is therefore now a verified input/profile-to-animation-action boundary, even though the configured record meanings remain partly open.
- `0x00492f20`, called from the action update immediately before `0x0049b010`, is the verified writer for animation `+0xf4/+0xf6`. It converts turn accumulator `+0x3148` into frame ranges `0..0x16` for states 6/7, and later ranges `0..0xc/0xf` for brake/turn states 9/10; profile `+0xb0` changes the turn limit from `0x2d000` to `0x5a000`. Native `ground_animation.*` now owns this state/frame update; animation asset/event dispatch remains outside the portable PlayerState boundary.
- Static disassembly of `0x00489a10` confirms the normalized-axis layout: controller bytes are read from the four-byte device sample at `0x0056afbd..0x0056afc0`, passed through `0x00489990`, and stored in `0x0056b140..0x0056b143`; the action threshold tests use byte `+0x149` for Left/Right and byte `+0x148` for Up/Down. Native `InputState` names these two semantic axes and retains them through fixed-step/session entry without claiming their later skater meaning.
- `0x00489cd0` runs before the per-frame poll in `0x004699f0` and copies four-word action snapshots through four pointer destinations per player. Its loop stride is `0x16c` bytes and it covers two player records; the two-player branch additionally rotates the recent snapshots. Native `InputState::history()` exposes the confirmed four-frame semantic depth while intentionally omitting the retail pointer-backed memory layout.
- In the same trace, the first counter word at record `+0x04` reset on activation and incremented once per update while held, while the second counter at `+0x08` reset on activation and incremented during the inactive interval. The `+0x0c` word advanced with the state-update cadence. These counter roles are recorded as behavior, not yet assigned final type names.
- Static `0x00489a10` confirms the complete low action bank mapping used by the native model: JUMP `+0x00/0x0010`, GRIND `+0x10/0x0080`, GRAB `+0x20/0x0020`, KICK `+0x30/0x0040`, SPINLEFT `+0x40/0x0004`, NOLLIE `+0x50/0x0001`, SPINRIGHT `+0x60/0x0008`, SWITCH `+0x70/0x0002`, then LEFT/RIGHT/UP/DOWN at `+0x80/+0x90/+0xa0/+0xb0`.
- The upstream JUMP/KICK handoff was checked through the action update boundary. `0x004e42c0` emits the two mask bits independently; `0x00489a10` passes `mask&0x10` to the `+0x00` record and `mask&0x40` to the `+0x30` record; and `0x00489930` only updates the selected record's held/edge/counter bytes before calling `0x00466b60`. The latter is an empty function in the recovered decompilation. No write to `player+0x2de0` or alias from bit `0x0010` to bit `0x0040` occurs in this chain.

## Interpretation

`PCInput_LoadBindings` is a verified naming anchor for configuration parsing. The per-loop poll, action-mask construction, complete movement mapping, movement-record edge behavior, sixteen-slot profile block, action-table reduction, stateful turn-animation writer, and first action-to-skater consumer are now identified.

The negative result is scoped to the input/action-update chain: it rules out a
direct JUMP-to-KICK alias at mask construction or record update, but does not
rule out a later gameplay/animation eligibility decision that presents the
KICK-gated prephysics path as the user-facing ollie action.

## Open questions / falsifiers

- Resolve configured meanings for the raw profile slots that are still only known by offset (`+0xc0..+0xf0`) and the exact gameplay meaning of the directional `+0xb0` branch.
- Connect the local-profile writers and `+0x2f2c` cooldown rearm conditions to the native ground-motion input. The `+0x2e78/+0x2e7c` turn flags, response-normalized transient, cooldown countdown, and `+0x2dc8` threshold service are already isolated or modeled.
